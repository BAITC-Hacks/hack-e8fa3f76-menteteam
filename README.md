# Alem Minutes

**Встреча закончилась. Поручения остались.** Локальный ассистент для совещаний на русском, казахском и смешанном языке: запись → стенограмма со спикерами → протокол с проверяемыми цитатами → контроль исполнения.

Whisper вызывается через Python API `faster-whisper`, Gemma — через `transformers` в том же процессе. Аудио и текст не отправляются во внешние inference API. Все задачи сначала становятся черновиками: секретарь проверяет имя, срок и цитату перед подтверждением.

## Быстрый запуск

Нужны Python 3.12–3.13, [uv](https://docs.astral.sh/uv/getting-started/installation/) и шрифт DejaVu Sans. Linux/WSL — основной проверяемый путь. Для мультимедиа и диаризации установите FFmpeg и libsndfile:

```bash
# Ubuntu / Debian
sudo apt-get install ffmpeg libsndfile1 fonts-dejavu-core
cp .env.example .env
./run-local.sh
```

Откройте `http://127.0.0.1:8501`. Основная конфигурация — **NVIDIA T4**, PyTorch 2.8 с CUDA 12.6. Нужны рабочий драйвер NVIDIA и доступ процесса к GPU (`nvidia-smi`). Gemma работает в FP16, Whisper — в `int8_float16`; перед переключением на Gemma модели распознавания освобождают VRAM. Gemma 4 E2B требует примерно 10 ГБ на диске; первое скачивание и загрузка занимают время. Отсутствие CUDA выводится как ошибка; явный CPU-режим: `AI_DEVICE=cpu`, `WHISPER_COMPUTE=int8` (для Gemma FP32 потребуется больше 20 ГБ RAM). Для других ОС нужны соответствующие FFmpeg/шрифты; это не проверенная здесь конфигурация.

Для быстрой демонстрации интерфейса **без весов и тяжёлых AI-зависимостей**:

```bash
uv sync --locked
uv run --no-sync streamlit run app.py
```

Нажмите **Открыть демонстрацию**, затем вкладку **Протоколы**. Демонстрация использует явно обозначенную синтетическую смешанную стенограмму и заранее заданные поручения; она не выдаётся за результат запуска моделей.

## Основной сценарий

1. Уведомите участников о записи и ИИ-транскрибации, подтвердите право на обработку.
2. Во вкладке **Новое совещание** (открывается первой) задайте дату и выберите файл, микрофон, запись вкладки или один из аудиопримеров. Для своего файла выберите **Файл → Загрузить MP3 или другую запись**: перетащите запись или нажмите **Browse files**. Допустимы MP3/WAV/M4A/FLAC/AAC/OGG/OPUS/MPGA/MP4/WebM/MPEG; максимум 200 МБ. Файл выбирается на вашем устройстве, обработка выполняется на сервере. После выбора доступны имя, размер и проигрыватель записи.
3. Запустите анализ. `auto` оставляет определение языка Whisper; доступны также `ru` и `kk`. Для качества казахской и смешанной речи можно выбрать `large-v3`, если хватает ресурсов; качество на вашей записи нужно измерить.
4. В **Протоколах** прослушайте образцы спикеров и подтвердите имена. Говорящий и ответственный хранятся отдельно: фраза «Айжан, подготовь отчёт» не назначается говорящему.
5. Проверьте цитаты и таймкоды, исправьте саммари/решения, ответственных, даты, срочность и направление поручений. Срок «завтра» / «ертең» считается от введённой даты; неоднозначные сроки требуют ручной проверки.
6. Отметьте поручение проверенным, при необходимости укажите email. История, правки и статусы сохраняются в SQLite и переживают перезапуск.
7. Скачайте DOCX/PDF, JSON для импорта в СЭД или ICS для календаря. Для демонстрации доступна обезличенная копия; проверьте свободный текст перед публикацией.
8. В **Обзоре поручений** фильтруйте задачи по статусу, людям, направлению и совещанию. Просрочка определяется из даты и статуса выполнения.

## Диаризация и локальные веса

Для первого скачивания [pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) примите условия модели и задайте `HF_TOKEN` с правом чтения в `.env`. После подготовки локальной копии токен не нужен для inference. Если диаризация недоступна, приложение явно показывает предупреждение и не утверждает, что спикеры распознаны.

[Gemma 4 E2B](https://huggingface.co/google/gemma-4-E2B-it) загружается через `AutoProcessor` и `AutoModelForMultimodalLM`. Большая стенограмма обрабатывается ограниченными фрагментами; итоговое саммари объединяет их краткие содержания. Ответ проверяется схемой, а поручения без цитаты из реальной стенограммы отбрасываются. Совпадение цитаты не доказывает правильность её интерпретации — предусмотрена проверка человеком.

Подготовьте веса на машине с доступом к Hugging Face:

```bash
uv sync --locked --extra ai --extra diarization
uv run --no-sync python prepare_models.py
```

`launch.py` перед запуском добавляет CUDA-библиотеки из установленных wheel-пакетов в `LD_LIBRARY_PATH`, как требуется Faster-Whisper. Системный CUDA Toolkit не заменяет CUDA-сборку PyTorch.

Скрипт подготовки скачает модели в `data/models` и напечатает настройки. Укажите абсолютные пути, актуальные **на целевой машине**:

```dotenv
WHISPER_MODEL=/opt/alem/data/models/whisper-small
GEMMA_MODEL=/opt/alem/data/models/gemma
DIARIZATION_MODEL=/opt/alem/data/models/diarization
ALEM_OFFLINE=1
```

В закрытый контур перенесите код, веса и подготовленные зависимости/образ. После подготовки запускайте без синхронизации зависимостей:

```bash
uv run --no-sync python launch.py
```

`ALEM_OFFLINE=1` запрещает Hugging Face сетевую загрузку; модели должны быть доступны локально. `run-local.sh` выполняет синхронизацию пакетов и предназначен для первичной установки. Телеметрия Streamlit, Hugging Face и pyannote отключена в конфигурации проекта.

## Teams, Zoom, Google Meet и live-аудио

Во вкладке **Новое совещание → Teams / Zoom / Meet** нажмите **Открыть локальную запись**. Локальная страница позволяет открыть проверенную ссылку платформы и записать звук выбранной вкладки через браузерный `getDisplayMedia`.

Войдите в веб-клиент участником «Alem Minutes — ведётся запись», отключите камеру/микрофон ассистента и дождитесь допуска организатора. Затем в Chrome/Edge выберите вкладку встречи и включите передачу её аудио. При необходимости добавьте свой микрофон. После остановки запись появится в списке live-записей; нажмите обновление и запустите анализ. Есть резервное скачивание аудио при сбое сохранения.

Это **подключение с участием оператора**: вход в аккаунт, выбор вкладки и допуск выполняются человеком. Автономный бот на официальных SDK платформ и потоковая выдача транскрипта во время записи не реализованы. Аудио захватывается вживую, анализ выполняется после остановки. Для настольного клиента платформы можно импортировать его запись; захват его системного звука зависит от ОС и браузера.

Сервис записи слушает только `127.0.0.1:8765`, использует случайный токен, проверки Host/Origin, подтверждение записи и ограничение размера. Открывать эту страницу нужно на компьютере, где запущено приложение. Браузерный механизм описан в [документации Chrome](https://developer.chrome.com/docs/extensions/how-to/web-platform/screen-capture).

## Автоматические напоминания и рассылка

Письма создаются только для **проверенных** незавершённых поручений с корректным email. Первое письмо содержит поручение и цитату; напоминания создаются ежедневно за три дня до срока и после просрочки. SQLite предотвращает повтор одного уведомления. Ошибка доставки допускает повторную попытку. При аварии между SMTP-доставкой и фиксацией в БД возможен повтор: получатель получает стабильный `Message-ID`.

По умолчанию worker сохраняет `.eml` локально и ничего не отправляет:

```bash
uv run --no-sync python notification_worker.py --interval 300
```

Настройте внутренний SMTP в `.env` и явно включите доставку:

```dotenv
SMTP_HOST=mail.internal.example
SMTP_PORT=587
SMTP_FROM=minutes@internal.example
SMTP_USER=minutes
SMTP_PASSWORD=replace-me
SMTP_STARTTLS=1
```

```bash
uv run --no-sync python notification_worker.py --send --interval 300
```

Вместо непрерывного процесса используйте cron/systemd с однократным запуском без `--interval`. Подготовленные локальные письма не подавляют последующую SMTP-рассылку: режимы имеют отдельные записи доставки. Уведомления не зависят от открытого Streamlit. Доступ к SMTP и адреса получателей настраивает заказчик; во время разработки реальные письма не отправлялись.

## Архитектура

```text
app.py / ui                 Streamlit: ввод, проверка, история, контроль
          ↓
services.pipeline           сборка зависимостей и кэш
          ↓
application.process         сценарий «запись → протокол»; интерфейсы ports
          ↓
core                        модели данных, цитаты, даты, правила ответственности
          ↑
adapters                    faster-whisper / pyannote / Transformers / SQLite

services.capture            локальный приём live-записи из браузера
notification_worker.py      независимая очередь писем и SMTP
exporters.py                Unicode DOCX/PDF, JSON, ICS, обезличивание
```

Модели загружаются лениво; тяжёлые вызовы сериализованы. На переходах Whisper/pyannote ↔ Gemma предыдущие модели освобождаются, чтобы укладываться в память T4. Внутри этапа модель переиспользуется для всех фрагментов. Ядро не импортирует UI, модельные библиотеки или SQLite. Ключ кэша — SHA-256 содержимого записи и настроек, поэтому локальные пути моделей безопасны. Правки пользователя хранятся отдельно от кэша inference. Совещания и поручения имеют стабильные ID независимо от названий.

## Проверки и воспроизводимость

```bash
./run-tests.sh
```

Фактические результаты, включая полный GPU-прогон, записаны в [отчёте проверки](docs/verification.md).

Тесты не скачивают веса. Проверяются цитаты и таймкоды, RU/KZ сроки, атрибуция, кэш с локальными путями, SQLite, повторная доставка, HTTP-защита записи, Unicode-экспорт и сохранение правок через настоящий Streamlit AppTest. CI выполняет их на Python 3.12.

Для воспроизводимого прогона реального аудио:

```bash
uv run --no-sync python launch.py process_recording.py data/meeting1.mp3 \
  --title 'Совещание 1' --date 2026-09-23 --language auto \
  --output data/cache/review-meeting1.json --no-cache
```

Сопоставьте результат с эталонной расшифровкой, проверьте имена, пропущенные/лишние поручения и диаризацию. Качество русского, казахского и смешанного языка нельзя подтвердить только тестами бизнес-логики. [Матрица требований и границ](docs/coverage.md) отделяет реализованные функции от интеграций, требующих окружения заказчика.

## Данные и развёртывание

`data/uploads` — загрузки и live-записи; `data/cache` — исходные результаты inference; `data/meetings.sqlite3` — история и правки; `data/outbox` — локальные письма; `data/models` — веса. Эти рабочие данные исключены из git. `ALEM_DATA_DIR` задаёт отдельный каталог. Реальные демонстрационные записи должны быть обезличены; поставляемые записи рассматривайте как данные, требующие проверки прав на использование.

Приложение рассчитано на секретаря на одном компьютере. Loopback не заменяет аутентификацию для совместного использования: для доступа по сети нужны аутентификация, TLS, разграничение доступа и резервные копии заказчика. Для чувствительных данных используйте шифрование диска и права ОС. Кнопка удаления очищает рабочую историю, кэш, загрузки и письма, сохраняя веса и поставляемые примеры; сначала остановите worker и запись.

Есть Dockerfile для подготовки CUDA-окружения. На хосте нужны драйвер NVIDIA и NVIDIA Container Toolkit. На Linux host networking сохраняет привязку обоих сервисов к loopback:

```bash
docker build -t alem-minutes .
docker run --rm --gpus all --network host --env-file .env \
  -v "$PWD/data:/app/data" alem-minutes
```

UID пользователя контейнера — 1000; каталог `data` должен быть ему доступен. В `.env` задавайте пути внутри контейнера, например `/app/data/models/gemma`. Образ нужно собрать до переноса в закрытый контур. Docker-развёртывание и реальные платформенные аккаунты требуют отдельной приёмки в окружении заказчика.
