# Alem Minutes

Локальный прототип для автоматического протоколирования совещаний на русском, казахском и смешанной русско-казахской речи. Система принимает аудио/видеофайл, распознаёт речь, разделяет спикеров, извлекает решения и поручения, показывает напоминания по срокам и экспортирует протокол в DOCX/PDF.

## Архитектура

```text
Streamlit UI
    └── services.pipeline (оркестрация, кэш, проверка evidence)
          ├── faster-whisper (локальная транскрибация)
          ├── pyannote Community-1 (локальная диаризация, опциональные веса)
          ├── services.llm → Transformers → Gemma (локальный Python inference)
          └── services.tracker → SQLite (статусы и напоминания)
```

Аудио и стенограмма не отправляются во внешние inference API. Whisper работает через Python API `faster-whisper`, Gemma загружается в тот же процесс Python через `transformers`; отдельный llama.cpp или другой сервер не используется. При первом запуске веса моделей загружаются из Hugging Face в `data/models`. Для полностью закрытого контура заранее поместите веса в локальное хранилище и укажите путь к ним в настройке Gemma.

## Требования

- Python 3.12 или 3.13, `uv`, `ffmpeg`.
- Для Gemma 4 E2B нужно около 10 GB места только под веса и дополнительная оперативная память для инференса. GPU ускоряет генерацию; CPU режим включён как fallback.
- Для полноценной диаризации примите условия `pyannote/speaker-diarization-community-1` на Hugging Face и задайте `HF_TOKEN`. Токен используется только для скачивания модели; аудио обрабатывается локально.

## Запуск

Linux / WSL:

```bash
sudo pacman -S uv ffmpeg ttf-dejavu
cp .env.example .env
./run-local.sh
```

Скрипт синхронизирует Python-зависимости и запускает интерфейс на `http://127.0.0.1:8501`. При первом старте скачиваются веса Faster-Whisper и Gemma. Чтобы использовать локальную копию Gemma, установите в `.env`:

```dotenv
GEMMA_MODEL=/path/to/gemma-4-E2B-it
WHISPER_MODEL=small
```

Настройка модели Whisper также доступна в боковой панели: `base`, `small`, `medium`, `large-v3-turbo`, `large-v3`. `auto` выбирает язык речи автоматически; можно явно выбрать `ru` или `kk`. Для смешанной речи оставьте `auto`.

## Сценарий демонстрации

1. Убедитесь, что участники уведомлены о записи и ИИ-транскрибации, затем отметьте подтверждение в боковой панели.
2. Загрузите тестовую запись MP3/WAV/M4A/MP4/WebM. Текстовые примеры ожидаемых протоколов находятся в `docs/meeting_minutes_*.txt`.
3. Нажмите **Распознать и составить протокол**.
4. Изучите краткое саммари, решения, поручения, цитаты, таймкоды и вопросы по неуверенно определённым владельцам/срокам.
5. В панели контроля установите для каждого поручения статус **В работе** или **Выполнено**. Статусы сохраняются локально в SQLite; явные календарные даты дают напоминания о просрочке и сроках в ближайшие три дня.
6. Скачайте итоговый DOCX или PDF. Экспорт включает транскрипт, задачи, владельцев, сроки, статусы и подтверждающие цитаты.

Поручение показывается только при наличии evidence-цитаты в распознанной речи. Таймкод берётся из соответствующего сегмента Whisper. Относительный срок вроде «в пятницу» сохраняется как текст; система не превращает его в дату без однозначного календарного контекста.

## Данные и приватность

- Перед обработкой интерфейс требует подтвердить уведомление участников о записи и транскрибации.
- Streamlit привязан к loopback (`127.0.0.1`); не открывайте его в общую сеть без собственной аутентификации и защищённого прокси.
- Локальные данные: `data/uploads` (загруженное аудио), `data/cache` (готовые протоколы), `data/tasks.sqlite3` (статусы). Они исключены из git.
- Раздел **Управление локальными данными** удаляет аудио, протоколы и статусы, оставляя загруженные веса моделей.
- Первичная загрузка весов обращается к Hugging Face; для офлайн/закрытого контура заранее подготовьте локальные каталоги моделей. После загрузки обработка может работать без сетевого доступа.
- Обезличивайте реальные записи перед демонстрацией.

## Границы прототипа

- На вход подаются записи через локальную загрузку. Нативное подключение ботом к Teams/Zoom/Google Meet и обработка live-потока требуют отдельных платформенных интеграций и в прототип не включены.
- Встроенные напоминания показываются в панели при открытии приложения; отправка email/мессенджер-уведомлений не настроена.
- Диаризация требует получения весов pyannote и не обещает биометрическую идентификацию человека. Связь speaker ID с реальным именем принимается только при явном подтверждении в речи.
- Русский, казахский и смешанная речь обрабатываются одной многоязычной моделью Whisper и анализируются Gemma. Качество зависит от записи и модели; важные поручения нужно сверять с цитатами.
- СЭД и промышленное многопользовательское развёртывание не входят в прототип.

## Структура проекта

- `app.py` — локальный пользовательский интерфейс.
- `services/pipeline.py` — обработка записи, кэширование и проверка evidence.
- `services/llm.py`, `services/model_registry.py` — Gemma inference и жизненный цикл модели.
- `services/tracker.py` — локальные статусы поручений и напоминания.
- `core/models.py` — типизированные модели транскрипта, поручений и протокола.
- `exporters.py` — экспорт в DOCX/PDF.
- `docs/meeting_minutes_*.txt` — демонстрационные транскрипты.
- `docs/requirements_ru_kz_en.txt` — исходное трёхъязычное ТЗ.
