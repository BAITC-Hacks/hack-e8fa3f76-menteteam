# Соответствие ТЗ и демонстрация

Основание: `requirements_ru_kz_en.txt`. Оценку выставляет жюри; проект не присваивает себе баллы без приёмки.

| Требование | Реализация | Подтверждение / граница |
|---|---|---|
| Speech-to-text | Faster-Whisper через Python, файлы и запись микрофона/вкладки | Нужны реальные веса; качество проверяется на аудио |
| Русский | Whisper `auto`/`ru`, исходный язык протокола | Тесты правил + отдельный аудиопрогон |
| Қазақша | Whisper `auto`/`kk`, Unicode во всех экспортах | Тесты казахских цитат/сроков; качество ASR требует аудио |
| Шала-казахский | Многоязычная модель, `auto`, смешанные цитаты | Синтетический смешанный пример явно помечен |
| Кто / что / срок | Gemma JSON, проверка цитат, нормализация дат, ручное подтверждение | `test_grounding.py`; неподтверждённые назначения не рассылаются |
| Диаризация и участник | Community-1, выравнивание слов Whisper, прослушивание и подтверждение имён | `test_adapters.py`; реальные веса требуют принятия условий |
| Саммари | Локальная Gemma по ограниченным фрагментам, редактирование результата | Без облачного inference; итог из саммари фрагментов |
| DOCX / PDF | Unicode-шрифт, поручения, сроки, статусы, цитаты, транскрипт | `test_exports.py` |
| Teams / Zoom / Meet | Подключение с оператором через веб-клиент, захват вкладки | `test_capture.py` проверяет URL/HTTP; реальные аккаунты не эмулируются |
| Live-поток | Живая запись вкладки и микрофона, локальное сохранение | Итоговый анализ после остановки; live-субтитров нет |
| Уведомление участников | Явное подтверждение перед записью/импортом, инструкция по имени ассистента | Подтверждение оператора, не автоматическое объявление всем участникам |
| Напоминания | Независимый worker, срок в 3 дня/просрочка, локальные EML или SMTP | Тесты одобрения, повторов, повторной попытки |
| Дашборд | История, поиск, в работе/просрочено/выполнено/черновик | SQLite и AppTest сохранения правок |
| Рассылка выдержек | Проверенное поручение + цитата отдельному адресату | Настраиваемый внутренний SMTP; реальные письма при разработке не отправляются |
| Срочность / направление | Поля Gemma с возможностью правки и фильтрации | Классификация — предложение модели, видимо редактору |
| СЭД (дополнительно) | Структурированный JSON с ID, датами, источниками и статусами | Формат файлового обмена; нативный API конкретной СЭД требует её контракта |
| Голосовая идентификация (дополнительно) | Диаризация внутри записи и подтверждение личности оператором | Межсессионная биометрическая идентификация по эталонам не реализована |
| Закрытый контур | Локальные веса, offline-флаги, инструкция подготовки и Dockerfile | Образ/целевая инфраструктура требуют отдельной приёмки |
| Приватность | Loopback, контроль записи, отключение телеметрии, локальное хранение, обезличенный экспорт, удаление | Сетевой многопользовательский режим требует защиты заказчика |

## Демонстрация за 5 минут

1. Открыть синтетическую демонстрацию и явно назвать её тестовым примером.
2. Показать русскую и казахскую реплику, владельца поручения и отдельно говорящего.
3. Исправить ответственное лицо/дату и подтвердить поручение; перезапустить интерфейс и показать сохранённую правку.
4. Найти задачу на дашборде, изменить статус, скачать Unicode PDF и календарь.
5. Подготовить локальные письма, показать повторный запуск без дублей.
6. Отдельно прогнать реальную запись через `process_recording.py` на машине с моделями. Сверить с эталоном и сообщить измеренную длительность, ошибки ASR и ошибки/пропуски поручений.

Пункты 1–5 демонстрируют приложение и правила обработки. Они не заменяют пункт 6 и не являются измерением качества нейросетей.
